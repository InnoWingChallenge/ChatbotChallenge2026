02 / 分类与 PROMPT · 点击类型切换指令

同一套事实规则，不同的提取重点

03 / 质量控制
审核通过后，才能入库
文字与数字
核对标题、日期、缩写、单位与标点。逐字转录；模糊部分标记 [unreadable]，不用主题知识补全。
数量与布局
只统计可见、能逐个辨认的物体。遮挡时给下限或说明不确定。左右方向统一为观看者视角。
证据与来源
图片可见事实与网页背景分开保存。年份、地点和人物身份需要证据；保留原图、网页链接和审核意见。
复杂海报或科研图：先看完整图，再用带重叠的局部裁剪提取小字；合并时保留位置关系并去掉重复文字。统计前区分图片数、活动数与画面物体数，同一物体跨照片不可直接累加。


04 / 小批试验 → 三人协作
先验证标准，再分批扩大
  1. 试处理 12–18 张：每类 2–3 张，覆盖两个网站及清晰、模糊和复杂画面。
  2. 只读描述做检查：能否回答原文、数量和位置问题？修改 prompt 后固定版本。
  3. 分配三份任务：在去重后的稳定清单上，按类型与难度均衡分工；每张图指定处理人和审核人。
  4. 分别保存，再统一合并：三个人使用相同字段和分类名称，各写独立结果文件；审核通过后统一入库。
A 审 B → B 审 C → C 审 A
处理人负责分类和描述，审核人逐项核对图片。困难图片交叉复核；每张图记录负责人、prompt 版本、实际模型和状态。
状态：pending → described → needs_review → approved
较强视觉模型先做样本与困难图；实际 API 部署需确认可用性。


05 / 最终产物
可重建，也可追溯
原图与来源清单分类与去重记录版本化 prompt审核后的图片描述检索元数据与审核记录
建议字段：image_id、src、source_pages、retrieved_at、content_hash、category、tags、visual_description、page_context、year / year_basis、zone / zone_basis、prompt_version、model、owner、reviewer、status。
比赛约束：在入库阶段完成图片理解，答题时使用缓存描述并满足每题 30 秒时限。重建文本索引后，重新加入图片描述索引。统计需按明确对象去重并获取完整匹配集合，不能把 top-k 检索结果当作总数。
